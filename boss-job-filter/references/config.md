# 输入与判定口径

示例仅展示格式，不作为默认个人资料：

```json
{
  "mode": "个人求职",
  "city": "深圳",
  "keywords": ["AI运营"],
  "limit": 150,
  "age": 35,
  "salary": {"min": 12000, "max": null, "unit": "月"},
  "degree": ["本科"],
  "experience": ["3-5年"],
  "scale": ["100-499人"]
}
```

城市使用明确的城市名；每任务一个城市。关键词为非空列表。`mode` 可选“个人求职”“市场调研”；默认根据上下文，缺省为个人求职。`limit` 为 1–150 的整数，默认 150，始终指去重原始数。

不筛年龄、薪资用 `null` 或省略；不筛学历、经验、规模用空列表 `[]` 或省略。不要填写含糊的条件，再任由脚本忽略。未知配置项会报错。

## 可选档位

| 条件 | 档位 |
|---|---|
| 学历 | 初中及以下、中专/中技、高中、大专、本科、硕士、博士、学历不限 |
| 经验 | 在校生、应届生、经验不限、1年以内、1-3年、3-5年、5-10年、10年以上 |
| 规模 | 0-20人、20-99人、100-499人、500-999人、1000-9999人、10000人以上 |

支持显式多选。只是用户说“不限制学历”时用 `[]`；只要页面“学历不限”岗位时用 `["学历不限"]`。只指定本科，不纳入大专或学历不限。任职者可能满足最低学历/经验不构成扩大档位的理由。

## 薪资

- 金额以元填写，`unit` 明确为“月”“天”“小时”“年”，至少提供一个边界。
- 按区间交集判断，边界相等有交集。最低月薪 12000 接受 10–15K 和 10–12K，不接受 8–10K。
- 比较同一计薪单位，不假定日薪换月薪的工作日，不用 13 薪提高月薪。
- 面议、混合底薪提成/综合薪资、无法读出的字体、单位未知或不同均待确认。即使列表数字可读，正文揭示综合薪资或提成结构，也需记录薪资待确认。

## 年龄与未知

- `age` 为求职者正整数年龄，仅从明确任职要求判断。
- 明确“35岁以下/以内/及以下”包含 35，“未满/小于35岁”不包含 35；“以上”包含边界，“超过”不包含边界。
- 未写、弹性例外、建议优先、相互冲突或未能解析，待确认。团队平均年龄、客户年龄、毕业年份不等于任职年龄限制。
- 所有已启用字段都区分“明确不限”和“没读到”；列表与详情冲突不得挑有利的一边。
- 详情读不完整或方向未核对，不能输出符合。

## 最终分流

任一启用条件有明确不符合证据 → 排除。无明确不符但有未知 → 待确认。全部通过且正文复核完成 → 符合。一个条件排除、另一个条件未知时仍排除。

两个模式共用上述规则，区别是使用目的和交付说明。首版不做跨任务历史去重；每次任务单独保存真实采集时间与数据，可用岗位标识比对不同批次。多关键词按顺序采集，共用 10 页和 150 条总预算；不得声称每个词都获得完整覆盖。
