# 完整 JD 的逐条复核

`prepare` 输出所有已读取详情的岗位、原始字段、全文、自动判定及指纹。分批阅读全文，不能只对标题或前 200 字判断。

对每条完成以下检查：

1. **方向**：职责是否属于用户要求的岗位方向。搜索命中不等于方向通过。AI 产品运营、用 AI 完成的内容运营可能符合“AI运营”；只销售 AI 产品的客户经理则属于销售。范围不清且会影响大量记录时补问；个别混合岗位可待确认。不能将本例固定为所有用户的排除清单。
2. **城市**：核对实际工作地点。用户指定城市与正文明确地点冲突时记录，不能拿总部地点替代岗位地点。
3. **年龄**：查看所有任职要求，确认自动提取的是求职者年龄限制。团队或客户年龄、柔性表述不得被当作硬性通过证据。
4. **薪资**：开启时核对单位、底薪/提成/综合口径及列表数字。正文揭示混合构成时，即使列表是数字区间也写入 `salary` 冲突/疑义，交由待确认。
5. **学历、经验、规模**：核对正文与列表/详情头部字段。学历“本科及以上”与列表本科通常一致；列表“不限”正文“本科、5年以上”有冲突。实习的“4天/周 3个月”是出勤安排，不能转换成年限经验档位。
6. **摘要**：写 1–2 句不超过 300 字的职责摘要，可保留有意义的混合职责、出勤或提成提示。不补充个人评价或未经核实的招聘承诺。

## 文件格式

```json
{
  "config_hash": "照抄 review-tasks.json 的 config_hash",
  "jobs": [
    {
      "job_id": "照抄岗位标识",
      "content_hash": "照抄该条 content_hash",
      "checked_requirements": true,
      "role": {
        "status": "通过",
        "reason": "职责明确为 AI 产品用户增长与社群运营",
        "evidence": "逐字复制本岗位 JD 中支持结论的完整句子"
      },
      "summary": "依据全文概括的实际职责。",
      "conflicts": [
        {
          "field": "salary",
          "reason": "列表给出区间，正文说明是底薪加提成的综合薪资",
          "evidence": "逐字复制本岗位薪资构成原文"
        }
      ]
    }
  ]
}
```

`role.status` 只能“通过”“待确认”“排除”，不能写最终状态“符合”。通过和排除必须有 JD 原句证据；待确认可以因无相关描述而没有引用，但必须说明缺少什么。

`checked_requirements=true` 仅在确已阅读并检查后填写；没读的条目留空缺失，由系统保持待确认。`conflicts` 无冲突时为 `[]`，字段限 city/age/salary/degree/experience/scale，支持原文之间冲突或自动解释存在疑义；只有本次启用的字段才影响结果。

`role.evidence`、冲突证据都必须为原始 JD 的连续子串；保留原字符，不把规范化后的句子当作原文。脚本校验指纹、岗位 ID 和逐字引用，拒绝串岗、过期复核及虚构证据。原文中的零宽字、兼容汉字等可能造成复制不一致；可用规范化文本定位，再提取对应原始句子。

条件改变时，用新任务副本记录“基于已有样本重新筛选”的范围，并重新 `prepare` 与复核；不能复用旧指纹或声称进行了新搜索。若新条件超出原搜索范围，应重新采集，不能将旧样本视为完整新结果。
